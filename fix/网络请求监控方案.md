# 网络请求监控方案

## 一、背景与目标

当前网络库基于 OkHttp + Retrofit 构建，业务层通过 `Net.instance.get()` / `postJson()` 等 Builder 模式发起请求，底层经过 `EncryptInterceptor`（字段加解密）、`HttpLoggingInterceptor`（日志）等拦截器链。缺乏统一的网络质量监控能力，排查线上问题时缺少关键数据（请求耗时、失败率、错误分布等）。

### 目标
1. **拦截器方式**：在 OkHttp 拦截器链中嵌入监控逻辑，对业务代码零侵入
2. **错误检测**：自动识别网络错误（DNS 解析失败、连接超时、读写超时、HTTP 4xx/5xx 等）
3. **异步上报**：失败数据通过后台线程上报到监控服务器，不阻塞请求/响应流程
4. **单请求控制**：支持按请求粒度控制是否开启监控上报（类似现有 `EncryptMarker` 的开关机制）
5. **上报逻辑可替换**：业务方可提供自定义上报实现（如写入本地文件、发送到自研平台等），未提供时使用内置默认上报
6. **不修改现有代码**：纯增量设计，新增文件，改动最小化

│                                                                   │

│                      ┌─────────▼──┐  ┌───▼──────────────┐       │

### 上报逻辑可替换设计 —— 策略模式

```
┌──────────────────────┐
│   IMonitorReportHandler   │  ← 抽象接口（net 模块定义）
│   + onEvent(event)       │
│   + flush()             │
│   + shutdown()          │
└───────────┬──────────────┘
            │
    ┌───────┴────────┐
    │                │
    ▼                ▼
┌───────────────┐  ┌──────────────────────┐
│ DefaultReport │  │ 业务自定义 Handler     │
│ Handler       │  │ (外部模块实现)         │
│               │  │                      │
│ 内置默认上报   │  │ class MyReporter:     │
│ - 内存队列    │  │   IMonitorReportHandler│
│ - 批量 HTTP  │  │ { ... }              │
│ - 降级策略    │  │                      │
└───────────────┘  └──────────────────────┘
```

**核心原则**：默认上报逻辑内置在 `net` 模块中，业务方**无需做任何事情**即可使用。如果业务方有自己的上报渠道（如 Firebase Crashlytics、自研 APM 平台、本地日志文件），只需实现 `IMonitorReportHandler` 接口并通过配置注入即可完全接管上报行为。

### 模块划分

| 模块 | 位置 | 职责 |
|------|------|------|
| `MonitorConfig` | `net` 模块 | 全局监控配置（上报地址、采样率、缓冲区大小等） |
| `MonitorMarker` | `net` 模块 | 请求级标记（开启/跳过监控），通过 OkHttp Typed Tag 传递 |
| `MonitorEvent` | `net` 模块 | 监控事件数据模型（请求/响应元信息 + 错误信息） |
| `MonitorInterceptor` | `net` 模块 | OkHttp Interceptor 实现，核心拦截逻辑 |
| `IMonitorReportHandler` | `net` 模块 | **上报策略抽象接口**，定义事件处理的契约 |
| `DefaultMonitorReportHandler` | `net` 模块 | **内置默认上报实现**（内存队列 + 批量 HTTP POST） |

### Handler 选择流程

```
MonitorInterceptor.onEvent(event)
              │
              ▼
    config.reportHandler != null ?
         │              │
    是 (业务自定义)    否 (未设置，使用默认)
         │              │
         ▼              ▼
  调用自定义实现    自动创建 DefaultMonitorReportHandler
  (如 Firebase /     (内部队列 → 批量 HTTP POST)
   本地文件 / 多通道)
```

**业务方体验**：
- **零配置**：什么都不做 → 自动使用 `DefaultMonitorReportHandler`，只需配置 `reportUrl`
- **轻度定制**：实现 `IMonitorReportHandler` 接口 → 完全控制数据流向
- **组合模式**：可在自定义 Handler 内部组合默认 Handler（如 HTTP + 本地文件双写）

所有新增类放置在 `com.itg.net.monitor` 包下，与现有加密模块 `com.itg.net.encrypt` 的组织方式一致。

## 三、数据模型设计

### 3.1 MonitorEvent（监控事件）

```kotlin
// 文件：net/src/main/java/com/itg/net/monitor/MonitorEvent.kt
package com.itg.net.monitor

import org.json.JSONObject

/**
 * 单次网络请求的监控事件
 *
 * 涵盖请求元信息、响应结果、异常类型和时序数据，
 * 序列化为 JSON 上报到监控服务器。
 */
data class MonitorEvent(
    // ===== 请求标识 =====
    val requestId: String,          // UUID，唯一标识一次请求
    val url: String,                // 完整请求 URL
    val method: String,             // GET / POST / PUT / DELETE
    val tag: String?,               // 请求 tag（业务标识）

    // ===== 时序数据（毫秒） =====
    val dnsStartMs: Long,           // DNS 解析开始时间（epochMillis）
    val dnsEndMs: Long,             // DNS 解析结束时间
    val connectStartMs: Long,       // TCP 连接开始时间
    val connectEndMs: Long,         // TCP 连接结束时间
    val tlsStartMs: Long,           // TLS 握手开始时间
    val tlsEndMs: Long,             // TLS 握手结束时间
    val requestStartMs: Long,       // 请求开始时间（进入拦截器）
    val requestEndMs: Long,         // 请求结束时间（收到响应/异常）
    val totalCostMs: Long,          // 总耗时

    // ===== 响应信息 =====
    val httpCode: Int,              // HTTP 状态码（异常时为 -1）
    val responseBodySize: Long,     // 响应体大小（字节）
    val contentType: String?,       // Content-Type

    // ===== 错误信息 =====
    val isSuccess: Boolean,         // 是否成功（无异常且 HTTP 2xx）
    val errorType: ErrorType,       // 错误分类枚举
    val errorMessage: String?,      // 异常消息
    val exceptionClass: String?,    // 异常类名（如 SocketTimeoutException）

    // ===== 网络环境 =====
    val networkType: String?,       // WIFI / 4G / 5G / UNKNOWN
    val carrierName: String?        // 运营商名称（可选）
) {
    enum class ErrorType {
        /** 成功 */
        NONE,
        /** DNS 解析失败（UnknownHostException） */
        DNS_ERROR,
        /** TCP 连接超时（ConnectException / SocketTimeoutException on connect） */
        CONNECT_TIMEOUT,
        /** TCP 连接被拒绝 */
        CONNECT_REFUSED,
        /** TLS/SSL 握手失败（SSLException） */
        SSL_ERROR,
        /** 读取超时（SocketTimeoutException on read） */
        READ_TIMEOUT,
        /** 写入超时 */
        WRITE_TIMEOUT,
        /** 连接池耗尽 / 无路由 */
        NO_ROUTE,
        /** HTTP 4xx 客户端错误 */
        HTTP_CLIENT_ERROR,
        /** HTTP 5xx 服务端错误 */
        HTTP_SERVER_ERROR,
        /** 响应体解析失败（如 JSON 格式错误） */
        PARSE_ERROR,
        /** 请求被取消 */
        CANCELLED,
        /** 未知错误 */
        UNKNOWN
    }

    fun toJson(): JSONObject = JSONObject().apply {
        put("requestId", requestId)
        put("url", url)
        put("method", method)
        put("tag", tag ?: "")
        put("dnsCostMs", dnsEndMs - dnsStartMs)
        put("connectCostMs", connectEndMs - connectStartMs)
        put("tlsCostMs", tlsEndMs - tlsStartMs)
        put("totalCostMs", totalCostMs)
        put("httpCode", httpCode)
        put("responseBodySize", responseBodySize)
        put("contentType", contentType ?: "")
        put("isSuccess", isSuccess)
        put("errorType", errorType.name)
        put("errorMessage", errorMessage ?: "")
        put("exceptionClass", exceptionClass ?: "")
        put("networkType", networkType ?: "")
        put("carrierName", carrierName ?: "")
        put("timestamp", requestStartMs)
    }
}
```

### 3.2 错误分类逻辑

```kotlin
// 在 MonitorInterceptor 中实现
private fun classifyError(
    e: IOException?,
    httpCode: Int,
    isCancelled: Boolean
): MonitorEvent.ErrorType {
    if (isCancelled) return ErrorType.CANCELLED

    if (e != null) {
        return when (e) {
            is java.net.UnknownHostException -> ErrorType.DNS_ERROR
            is java.net.ConnectException -> {
                if (e.message?.contains("refused", ignoreCase = true) == true)
                    ErrorType.CONNECT_REFUSED
                else
                    ErrorType.CONNECT_TIMEOUT
            }
            is javax.net.ssl.SSLException -> ErrorType.SSL_ERROR
            is java.net.SocketTimeoutException -> {
                // 通过消息区分连接超时 vs 读取超时
                if (e.message?.contains("connect", ignoreCase = true) == true)
                    ErrorType.CONNECT_TIMEOUT
                else
                    ErrorType.READ_TIMEOUT
            }
            else -> ErrorType.UNKNOWN
        }
    }

    return when {
        httpCode in 200..299 -> ErrorType.NONE
        httpCode in 400..499 -> ErrorType.HTTP_CLIENT_ERROR
        httpCode >= 500 -> ErrorType.HTTP_SERVER_ERROR
        else -> ErrorType.UNKNOWN
    }
}

### 4.1 MonitorMarker（对标 EncryptMarker）

```kotlin
// 文件：net/src/main/java/com/itg/net/monitor/MonitorMarker.kt
package com.itg.net.monitor

/**
 * 单次请求的监控开关标记
 *
 * 通过 OkHttp Typed Tag（class-based tag）传递，不占用 [okhttp3.Request.tag(Any)]。
 *
 * ## 优先级（由高到低）
 * 1. 请求级 MONITOR → 强制开启
 * 2. 请求级 SKIP    → 强制跳过
 * 3. 全局 enableMonitor 配置 → 兜底
 *
 * ## 使用方式
 * 通过 Builder 扩展方法设置：
 * ```
 * Net.instance.postJson()
 *     .url("...")
 *     .monitor()       // 强制开启监控
 *     .send(callback)
 *
 * Net.instance.get()
 *     .url("...")
 *     .skipMonitor()   // 跳过监控
 *     .send(callback)
 * ```
 */
enum class MonitorMarker {
    /** 请求级强制开启监控 */
    MONITOR,
    /** 请求级强制跳过监控 */
    SKIP;
}

/**
 * 从外部设置的标记值转换为 [MonitorMarker]
 *
 * 使用 String 传递以避免模块间直接依赖枚举类型，
 * 参考 [com.itg.net.encrypt.EncryptMarker.fromFlag] 的实现。
 */
fun monitorMarkerFromFlag(flag: String?): MonitorMarker? {
    return when (flag?.uppercase()) {
        "MONITOR" -> MonitorMarker.MONITOR
        "SKIP" -> MonitorMarker.SKIP
        else -> null
    }
}
```

## 五、MonitorInterceptor 设计

### 5.1 核心拦截逻辑

```kotlin
// 文件：net/src/main/java/com/itg/net/monitor/MonitorInterceptor.kt
package com.itg.net.monitor

import android.content.Context
import android.net.ConnectivityManager
import android.net.NetworkCapabilities
import okhttp3.*
import java.io.IOException
import java.util.UUID
import java.util.concurrent.ExecutorService
import java.util.concurrent.Executors

/**
 * 网络请求监控拦截器
 *
 * ## 工作机制
 * 1. 记录请求进入时的精确时间戳
 * 2. 调用 [chain.proceed] 执行实际请求
 * 3. 无论成功还是失败，构建 [MonitorEvent] 并通过 [IMonitorReportHandler] 上报
 * 4. 上报过程完全异步，不阻塞响应返回
 *
 * ## 开关优先级
 * 1. 请求级标记 [MonitorMarker.MONITOR] → 强制开启
 * 2. 请求级标记 [MonitorMarker.SKIP] → 强制跳过
 * 3. 全局配置 [MonitorConfig.enabled] → 兜底
 *
 * ## 性能保障
 * - 事件构建使用 StringBuilder/JSONObject，避免反射开销
 * - 上报通过专用线程池异步执行
 * - 失败事件的 JSON 序列化在后台线程完成
 */
class MonitorInterceptor(
    private val config: MonitorConfig,
    private val reportHandler: IMonitorReportHandler,  // 抽象接口，默认 DefaultMonitorReportHandler
    private val context: Context?
) : Interceptor {

    companion object {
        private const val TAG = "MonitorInterceptor"
    }

    /** 轻量级后台线程池，仅用于事件构建和投递 */
    private val executor: ExecutorService = Executors.newSingleThreadExecutor { r ->
        Thread(r, "monitor-event").apply {
            isDaemon = true           // 守护线程，不阻止进程退出
            priority = Thread.MIN_PRIORITY
        }
    }

    override fun intercept(chain: Interceptor.Chain): Response {
        val request = chain.request()
        val requestId = UUID.randomUUID().toString()
        val requestStartMs = System.currentTimeMillis()

        // === 第1步：判断是否需要对本次请求监控 ===
        val shouldMonitor = shouldMonitor(request)

        if (!shouldMonitor) {
            // 跳过监控，直接透传
            return chain.proceed(request)
        }

        // === 第2步：执行实际请求（带异常捕获） ===
        var response: Response? = null
        var ioException: IOException? = null
        val requestEndMs: Long

        try {
            response = chain.proceed(request)
            requestEndMs = System.currentTimeMillis()
        } catch (e: IOException) {
            requestEndMs = System.currentTimeMillis()
            ioException = e
        }

        // === 第3步：异步构建事件并入队上报 ===
        // 使用 copy of local vals 避免 lambda 捕获可变变量的问题
        val finalResponse = response
        val finalException = ioException
        val finalEndMs = requestEndMs

        executor.submit {
            try {
                val event = buildEvent(
                    request = request,
                    requestId = requestId,
                    requestStartMs = requestStartMs,
                    requestEndMs = finalEndMs,
                    response = finalResponse,
                    exception = finalException
                )

                // 根据配置决定是否上报
                // 默认：仅失败时上报；可配置为全量上报
                if (config.reportMode.shouldReport(event)) {
                    reporter.enqueue(event)
                }
            } catch (e: Exception) {
                // 监控自身异常静默吞掉，不影响业务
            }
        }

        // === 第4步：返回结果（异常重新抛出，与 OkHttp 约定一致） ===
        if (finalException != null) {
            throw finalException
        }
        return finalResponse!!
    }

    // ==================== 开关判断 ====================

    /**
     * 判断是否需要对本次请求进行监控
     *
     * 优先级链：
     * 1. 请求级 MONITOR → true
     * 2. 请求级 SKIP    → false
     * 3. 全局 enabled    → 兜底
     */
    private fun shouldMonitor(request: Request): Boolean {
        val marker = request.tag(MonitorMarker::class.java)
        if (marker == MonitorMarker.MONITOR) return true
        if (marker == MonitorMarker.SKIP) return false
        return config.enabled
    }

    // ==================== 事件构建 ====================

    private fun buildEvent(
        request: Request,
        requestId: String,
        requestStartMs: Long,
        requestEndMs: Long,
        response: Response?,
        exception: IOException?
    ): MonitorEvent {
        val httpCode = response?.code ?: -1
        val isCancelled = exception is IOException &&
            exception.message?.contains("Canceled", ignoreCase = true) == true

        return MonitorEvent(
            requestId = requestId,
            url = request.url.toString(),
            method = request.method,
            tag = request.tag(String::class.java) ?: request.tag(Any::class.java)?.toString(),

            // 时序数据（OkHttp 4.x EventListener 可获取精确阶段耗时，
            // 拦截器层只能获取总耗时和各阶段大致时间。
            // 精确方案见第七章进阶优化）
            dnsStartMs = 0,
            dnsEndMs = 0,
            connectStartMs = 0,
            connectEndMs = 0,
            tlsStartMs = 0,
            tlsEndMs = 0,

            requestStartMs = requestStartMs,
            requestEndMs = requestEndMs,
            totalCostMs = requestEndMs - requestStartMs,

            httpCode = httpCode,
            responseBodySize = response?.body?.contentLength() ?: -1,
            contentType = response?.body?.contentType()?.toString(),

            isSuccess = exception == null && httpCode in 200..299,
            errorType = classifyError(exception, httpCode, isCancelled),
            errorMessage = exception?.message,
            exceptionClass = exception?.javaClass?.simpleName,

            networkType = getNetworkType(),
            carrierName = null
        )
    }

    private fun classifyError(
        e: IOException?,
        httpCode: Int,
        isCancelled: Boolean
    ): MonitorEvent.ErrorType {
        if (isCancelled) return MonitorEvent.ErrorType.CANCELLED

        if (e != null) {
            return when (e) {
                is java.net.UnknownHostException -> MonitorEvent.ErrorType.DNS_ERROR
                is java.net.ConnectException -> {
                    if (e.message?.contains("refused", ignoreCase = true) == true)
                        MonitorEvent.ErrorType.CONNECT_REFUSED
                    else
                        MonitorEvent.ErrorType.CONNECT_TIMEOUT
                }
                is javax.net.ssl.SSLException -> MonitorEvent.ErrorType.SSL_ERROR
                is java.net.SocketTimeoutException -> {
                    if (e.message?.contains("connect", ignoreCase = true) == true)
                        MonitorEvent.ErrorType.CONNECT_TIMEOUT
                    else
                        MonitorEvent.ErrorType.READ_TIMEOUT
                }
                else -> MonitorEvent.ErrorType.UNKNOWN
            }
        }

        return when {
            httpCode in 200..299 -> MonitorEvent.ErrorType.NONE
            httpCode in 400..499 -> MonitorEvent.ErrorType.HTTP_CLIENT_ERROR
            httpCode >= 500 -> MonitorEvent.ErrorType.HTTP_SERVER_ERROR
            else -> MonitorEvent.ErrorType.UNKNOWN
        }
    }

    // ==================== 网络状态获取 ====================

    @Suppress("DEPRECATION")
    private fun getNetworkType(): String? {
        val ctx = context ?: return null
        return try {
            val cm = ctx.getSystemService(Context.CONNECTIVITY_SERVICE) as? ConnectivityManager
            val network = cm?.activeNetwork ?: return "NONE"
            val caps = cm.getNetworkCapabilities(network) ?: return "UNKNOWN"
            when {
                caps.hasTransport(NetworkCapabilities.TRANSPORT_WIFI) -> "WIFI"
                caps.hasTransport(NetworkCapabilities.TRANSPORT_CELLULAR) -> "CELLULAR"
                caps.hasTransport(NetworkCapabilities.TRANSPORT_ETHERNET) -> "ETHERNET"
                else -> "OTHER"
            }
        } catch (e: Exception) {
            "UNKNOWN"
        }
    }
}
```

## 六、上报处理器设计（可替换策略）

### 6.1 设计思想

上报逻辑是业务方最可能有定制需求的环节。不同业务对接的上报通道各不相同：

- 有的使用公司自研 APM 平台
- 有的使用 Firebase Crashlytics / Performance
- 有的只需要写本地日志文件
- 有的需要同时上报到多个通道

因此，将上报逻辑抽象为接口，内置提供一套默认实现，业务方可以**完全替换**为自定义实现。核心原则：

> **默认即用，按需替换 —— 业务方零配置即可使用默认上报，有特殊需求时注入自定义 Handler。**

### 6.2 IMonitorReportHandler 接口

```kotlin
// 文件：net/src/main/java/com/itg/net/monitor/IMonitorReportHandler.kt
package com.itg.net.monitor

/**
 * 监控事件上报处理器接口
 *
 * 定义监控事件从产生到最终落地的完整生命周期契约。
 * net 模块只依赖此接口，不关心具体实现。
 *
 * ## 实现者需要注意
 * - [onEvent] 会在拦截器的工作线程中调用，实现方应尽快返回，
 *   耗时操作（网络 IO、文件写入等）在实现内部异步化
 * - [flush] 在以下时机被调用：
 *   1. App 进入后台时
 *   2. 进程即将终止时
 *   3. 定时触发（由实现方自行决定）
 * - [shutdown] 在 OkHttpClient 被释放时调用，确保数据不丢失
 *
 * ## 自定义实现示例
 * ```kotlin
 * // 示例1：接入 Firebase Crashlytics
 * class FirebaseReportHandler : IMonitorReportHandler {
 *     override fun onEvent(event: MonitorEvent) {
 *         if (!event.isSuccess) {
 *             FirebaseCrashlytics.getInstance().log(event.toJson().toString())
 *         }
 *     }
 *     override fun flush() {}  // Firebase 实时上报，无需 flush
 *     override fun shutdown() {}
 * }
 *
 * // 示例2：同时写入本地文件 + HTTP 上报
 * class DualReportHandler(
 *     private val httpReporter: DefaultMonitorReportHandler,
 *     private val logFile: File
 * ) : IMonitorReportHandler {
 *     override fun onEvent(event: MonitorEvent) {
 *         httpReporter.onEvent(event)          // HTTP 上报
 *         logFile.appendText(event.toJson().toString() + "\n")  // 本地备份
 *     }
 *     override fun flush() { httpReporter.flush() }
 *     override fun shutdown() { httpReporter.shutdown() }
 * }
 * ```
 */
interface IMonitorReportHandler {

    /**
     * 接收单条监控事件
     *
     * 在拦截器工作线程中被调用。实现方应：
     * - 尽快返回，避免阻塞拦截器链
     * - 内部自行处理异步化（入队、写磁盘等）
     *
     * @param event 监控事件，包含请求元信息、错误类型、时序数据等
     */
    fun onEvent(event: MonitorEvent)

    /**
     * 主动刷新缓冲区
     *
     * 适用于批量上报场景（如攒够 N 条再发 HTTP），
     * 在 App 进入后台或进程终止前调用，避免数据丢失。
     * 对于实时上报的实现（如直接写文件），可为空实现。
     */
    fun flush()

    /**
     * 关闭处理器，释放资源
     *
     * 在 OkHttpClient 被回收时调用。实现方应在此方法中：
     * - 等待缓冲区中的数据全部处理完成
     * - 关闭线程池/文件句柄/网络连接等资源
     * - 确保不丢失未上报的数据
     */
    fun shutdown()
}
```

### 6.3 DefaultMonitorReportHandler（内置默认实现）

```kotlin
// 文件：net/src/main/java/com/itg/net/monitor/DefaultMonitorReportHandler.kt
package com.itg.net.monitor

import android.util.Log
import okhttp3.*
import okhttp3.MediaType.Companion.toMediaType
import okhttp3.RequestBody.Companion.toRequestBody
import org.json.JSONArray
import org.json.JSONObject
import java.util.concurrent.*
import java.util.concurrent.atomic.AtomicBoolean

/**
 * 默认的监控事件上报处理器
 *
 * 实现 [IMonitorReportHandler] 接口，提供开箱即用的上报能力。
 * 业务方未注入自定义 Handler 时，框架自动使用此实现。
 *
 * ## 核心机制
 * - **内存缓冲**：使用 [LinkedBlockingQueue] 缓存事件，默认容量 1000
 * - **批量上报**：攒够 batchSize 条或到达 flushIntervalMs 时间窗口，触发批量 HTTP POST
 * - **后台线程**：单线程消费队列 → JSON 序列化 → HTTP POST
 * - **降级策略**：队列满时丢弃最旧事件；上报失败记录日志，不重试
 *
 * ## 线程模型
 * ```
 * MonitorInterceptor worker thread → onEvent(event) → LinkedBlockingQueue
 *                                                           │
 * Consumer thread                ← take() batch ← ─────────┘
 *                                     │
 *                                     ▼
 *                             POST /api/monitor/report
 * ```
 *
 * @param reportUrl 监控数据接收地址
 * @param batchSize 单次批量上报的最大事件数，默认 20
 * @param flushIntervalMs 上报时间窗口（毫秒），默认 10 秒
 * @param maxQueueSize 内存队列最大容量，默认 1000
 */
class DefaultMonitorReportHandler(
    private val reportUrl: String,
    private val batchSize: Int = 20,
    private val flushIntervalMs: Long = 10_000L,
    private val maxQueueSize: Int = 1000
) : IMonitorReportHandler {

    companion object {
        private const val TAG = "DefaultMonitorReport"
        private val JSON_MEDIA_TYPE = "application/json; charset=utf-8".toMediaType()
    }

    /** 事件缓冲队列 */
    private val queue: BlockingQueue<MonitorEvent> = LinkedBlockingQueue(maxQueueSize)

    /** 是否正在运行 */
    private val running = AtomicBoolean(true)

    /** 上报使用的 OkHttpClient（独立实例，避免与业务共用连接池） */
    private val reportClient: OkHttpClient = OkHttpClient.Builder()
        .connectTimeout(5, TimeUnit.SECONDS)
        .readTimeout(10, TimeUnit.SECONDS)
        .writeTimeout(10, TimeUnit.SECONDS)
        .retryOnConnectionFailure(false)
        .build()

    /** 消费者线程 */
    private val consumerThread: Thread = Thread({
        val batch = mutableListOf<MonitorEvent>()
        var lastFlushTime = System.currentTimeMillis()

        while (running.get()) {
            try {
                val event = queue.poll(1, TimeUnit.SECONDS)
                if (event != null) {
                    batch.add(event)
                }

                val shouldFlush = batch.size >= batchSize ||
                    (batch.isNotEmpty() &&
                     System.currentTimeMillis() - lastFlushTime >= flushIntervalMs)

                if (shouldFlush) {
                    doFlush(batch.toList())
                    batch.clear()
                    lastFlushTime = System.currentTimeMillis()
                }
            } catch (e: InterruptedException) {
                Thread.currentThread().interrupt()
                break
            } catch (e: Exception) {
                Log.w(TAG, "Consumer error", e)
            }
        }

        if (batch.isNotEmpty()) {
            doFlush(batch.toList())
        }
    }, "monitor-reporter").apply {
        isDaemon = true
    }

    init {
        consumerThread.start()
    }

    // ==================== IMonitorReportHandler 实现 ====================

    /**
     * 接收事件并入队
     *
     * - 队列未满：正常入队，立即返回
     * - 队列已满：移除最旧事件后入队（丢弃策略）
     * - 已 shutdown：静默丢弃
     */
    override fun onEvent(event: MonitorEvent) {
        if (!running.get()) return
        if (!queue.offer(event)) {
            queue.poll()   // 丢弃最旧
            queue.offer(event)
        }
    }

    /**
     * 立即刷新队列中所有未上报的事件
     */
    override fun flush() {
        val pending = mutableListOf<MonitorEvent>()
        queue.drainTo(pending)
        if (pending.isNotEmpty()) {
            doFlush(pending)
        }
    }

    /**
     * 关闭上报器，等待剩余事件上报完成后释放资源
     */
    override fun shutdown() {
        running.set(false)
        consumerThread.interrupt()
        try {
            consumerThread.join(5000)
        } catch (e: InterruptedException) {
            // ignore
        }
        // 最后一次机会：排空队列
        val remaining = mutableListOf<MonitorEvent>()
        queue.drainTo(remaining)
        if (remaining.isNotEmpty()) {
            doFlush(remaining)
        }
        reportClient.dispatcher.executorService.shutdown()
        reportClient.connectionPool.evictAll()
    }

    // ==================== 内部实现 ====================

    /**
     * 批量 HTTP 上报
     */
    private fun doFlush(events: List<MonitorEvent>) {
        if (events.isEmpty()) return

        try {
            val jsonArray = JSONArray()
            for (event in events) {
                jsonArray.put(event.toJson())
            }

            val body = JSONObject().apply {
                put("events", jsonArray)
                put("appVersion", getAppVersion())
                put("platform", "android")
                put("timestamp", System.currentTimeMillis())
            }

            val request = Request.Builder()
                .url(reportUrl)
                .post(body.toString().toRequestBody(JSON_MEDIA_TYPE))
                .build()

            val response = reportClient.newCall(request).execute()
            if (response.isSuccessful) {
                Log.d(TAG, "Reported ${events.size} events successfully")
            } else {
                Log.w(TAG, "Report failed: HTTP ${response.code}")
            }
            response.close()
        } catch (e: Exception) {
            Log.w(TAG, "Report exception: ${e.message}")
        }
    }

    private fun getAppVersion(): String = "unknown"
}
```

## 七、MonitorConfig 全局配置设计

```kotlin
// 文件：net/src/main/java/com/itg/net/monitor/MonitorConfig.kt
package com.itg.net.monitor

/**
 * 网络监控全局配置
 *
 * 通过 [com.itg.net.config.NetConfig] 的扩展方法设置，
 * 类似 [com.itg.net.config.NetConfig.encrypt] 的 DSL 风格。
 *
 * ## 使用示例
 * ```
 * Net.instance.configure {
 *     monitor {
 *         enabled(true)
 *         reportUrl("https://monitor.example.com/api/report")
 *         reportMode(ReportMode.FAILURE_ONLY)
 *         sampleRate(1.0f)  // 全量采样
 *     }
 * }
 * ```
 */
class MonitorConfig {
    /** 全局开关：是否启用监控 */
    @Volatile var enabled: Boolean = false

    /** 监控数据上报地址（默认上报器使用） */
    @Volatile var reportUrl: String? = null

    /** 上报模式 */
    @Volatile var reportMode: ReportMode = ReportMode.FAILURE_ONLY

    /** 采样率 0.0 ~ 1.0，1.0 表示全量 */
    @Volatile var sampleRate: Float = 1.0f

    /** 单次批量上报的最大事件数（默认上报器使用） */
    @Volatile var batchSize: Int = 20

    /** 上报时间窗口（毫秒），超过此时间即使未满 batchSize 也触发上报 */
    @Volatile var flushIntervalMs: Long = 10_000L

    /** 内存队列最大容量（默认上报器使用） */
    @Volatile var maxQueueSize: Int = 1000

    /**
     * 慢请求阈值（毫秒），超过此阈值的成功请求也会记录（可选）
     * 设为 0 表示不启用慢请求检测
     */
    @Volatile var slowRequestThresholdMs: Long = 0

    // ==================== 自定义上报 ====================

    /**
     * 自定义上报处理器
     *
     * - 当此值为 **null** 时（默认），框架自动创建 [DefaultMonitorReportHandler]
     *   并使用 [reportUrl]、[batchSize]、[flushIntervalMs]、[maxQueueSize] 参数
     * - 当业务方注入自定义实现时，**完全接管**上报行为，
     *   上述四个参数不再生效（由自定义实现自行处理）
     *
     * ## 使用示例
     * ```kotlin
     * // 示例1：使用默认上报（无需设置 reportHandler）
     * monitor {
     *     enabled(true)
     *     reportUrl("https://monitor.example.com/api/report")
     *     batchSize(30)
     * }
     *
     * // 示例2：注入自定义上报处理器
     * monitor {
     *     enabled(true)
     *     reportHandler(MyCustomReportHandler())  // ← 完全接管
     * }
     *
     * // 示例3：基于 Firebase 的上报
     * monitor {
     *     enabled(true)
     *     reportHandler(object : IMonitorReportHandler {
     *         override fun onEvent(event: MonitorEvent) {
     *             FirebaseCrashlytics.getInstance().log(event.toJson().toString())
     *         }
     *         override fun flush() {}
     *         override fun shutdown() {}
     *     })
     * }
     * ```
     */
    @Volatile var reportHandler: IMonitorReportHandler? = null
}

/**
 * 上报模式
 */
enum class ReportMode {
    /** 仅上报失败请求 */
    FAILURE_ONLY,
    /** 上报所有请求（成功 + 失败） */
    ALL,
    /** 仅上报成功但慢的请求（与 slowRequestThresholdMs 配合） */
    SLOW_ONLY;

    fun shouldReport(event: MonitorEvent): Boolean {
        return when (this) {
            FAILURE_ONLY -> !event.isSuccess
            ALL -> true
            SLOW_ONLY -> event.isSuccess
            // && event.totalCostMs > slowRequestThresholdMs  由调用方判断
        }
    }
}

## 八、OkHttpManager 集成方式

### 在 OkHttpManager 中注册拦截器

```kotlin
// OkHttpManager.createDefaultClient 中的新增代码段（概念示意）
// 监控拦截器：在 EncryptInterceptor 之后、LoggingInterceptor 之前注册
// 这样可以获取到解密后的明文，同时日志中能看到原始响应
ddNetConfig.monitorConfig?.let { monitorConfig ->
    if (monitorConfig.enabled) {
        // ===== 核心：选择上报处理器 =====
        // 业务方注入了自定义 Handler → 使用自定义实现
        // 业务方未注入 → 使用默认 HTTP 批量上报
        val handler = monitorConfig.reportHandler
            ?: DefaultMonitorReportHandler(
                reportUrl = monitorConfig.reportUrl ?: "",
                batchSize = monitorConfig.batchSize,
                flushIntervalMs = monitorConfig.flushIntervalMs,
                maxQueueSize = monitorConfig.maxQueueSize
            )

        builder.addInterceptor(MonitorInterceptor(
            config = monitorConfig,
            reportHandler = handler,   // 依赖抽象接口
            context = ddNetConfig.application
        ))
    }
}
```

**关键逻辑**：`monitorConfig.reportHandler ?: DefaultMonitorReportHandler(...)` 
- 如果 `reportHandler` 为 `null`（业务方未设置），自动创建默认上报器
- 如果 `reportHandler` 不为 `null`（业务方注入了自定义实现），直接使用，`reportUrl`/`batchSize` 等参数不再生效

### 拦截器链顺序

```
Request
  │
  ▼
[1. 用户自定义 Interceptor]     ← NetConfig.addInterceptor()
  │
  ▼
[2. EncryptInterceptor]          ← 字段加解密（请求加密）
  │
  ▼
[3. MonitorInterceptor]          ← ★ 网络监控（新增）
  │
  ▼
[4. HttpLoggingInterceptor]      ← 日志（作为 NetworkInterceptor）
  │
  ▼
Server
```

**顺序说明**：
- MonitorInterceptor 放在 EncryptInterceptor 之后：监控到的请求是加密后的（保护敏感数据不泄露到监控服务器）
- 如果业务需要监控明文，可放在 EncryptInterceptor 之前

### 9.5 自定义上报处理器

```kotlin
// ===== 场景1：接入 Firebase Crashlytics =====
class FirebaseReportHandler : IMonitorReportHandler {
    override fun onEvent(event: MonitorEvent) {
        // 仅上报失败事件
        if (!event.isSuccess) {
            val json = event.toJson().toString()
            FirebaseCrashlytics.getInstance().log(json)
            // 对于严重错误（如 5xx），可记录为自定义异常
            if (event.httpCode >= 500) {
                FirebaseCrashlytics.getInstance().recordException(
                    Exception("ServerError: ${event.url} -> ${event.httpCode}")
                )
            }
        }
    }
    override fun flush() {}    // Firebase 实时上报，无需批量
    override fun shutdown() {} // 无需额外清理
}

// 配置注入
Net.instance.configure {
    monitor {
        enabled(true)
        reportHandler(FirebaseReportHandler())  // ← 完全接管上报
    }
}

// ===== 场景2：写本地日志文件（适合离线诊断） =====
class FileReportHandler(
    private val logFile: File
) : IMonitorReportHandler {
    private val writer = logFile.bufferedWriter()

    override fun onEvent(event: MonitorEvent) {
        synchronized(writer) {
            writer.write(event.toJson().toString())
            writer.newLine()
            writer.flush()  // 每条都刷盘，防止丢失
        }
    }
    override fun flush() {}      // 已经在 onEvent 中实时写入
    override fun shutdown() {
        synchronized(writer) { writer.close() }
    }
}

// ===== 场景3：多通道同时上报（HTTP + 本地文件） =====
class MultiChannelReportHandler(
    private val httpHandler: DefaultMonitorReportHandler,
    private val fileHandler: FileReportHandler
) : IMonitorReportHandler {
    override fun onEvent(event: MonitorEvent) {
        httpHandler.onEvent(event)   // HTTP 上报到服务器
        fileHandler.onEvent(event)   // 同时写入本地文件备份
    }
    override fun flush() {
        httpHandler.flush()
        fileHandler.flush()
    }
    override fun shutdown() {
        httpHandler.shutdown()
        fileHandler.shutdown()
    }
}

// 配置注入
Net.instance.configure {
    monitor {
        enabled(true)
        reportHandler(MultiChannelReportHandler(
            httpHandler = DefaultMonitorReportHandler("https://monitor.example.com/api/report"),
            fileHandler = FileReportHandler(File(cacheDir, "network_monitor.log"))
        ))
    }
}

// ===== 场景4：仅打印 Log（调试用） =====
Net.instance.configure {
    monitor {
        enabled(true)
        reportHandler(object : IMonitorReportHandler {
            override fun onEvent(event: MonitorEvent) {
                if (!event.isSuccess) {
                    Log.e("NetworkMonitor", "请求失败: ${event.url} " +
                        "错误类型=${event.errorType} 耗时=${event.totalCostMs}ms " +
                        "异常=${event.errorMessage}")
                }
            }
            override fun flush() {}
            override fun shutdown() {}
        })
    }
}
```

## 十一、进阶优化（后续可迭代）

### 11.1 精确时序采集（OkHttp EventListener）
当前拦截器层只能获取总耗时。如需精确的 DNS/TCP/TLS 各阶段耗时，可配合 OkHttp 的 `EventListener`：

```kotlin
class MonitorEventListener(
    private val requestId: String,
    private val reportHandler: IMonitorReportHandler
) : EventListener() {
    private val timings = mutableMapOf<String, Long>()

    override fun dnsStart(call: Call, domainName: String) {
        timings["dnsStart"] = System.currentTimeMillis()
    }
    override fun dnsEnd(call: Call, domainName: String, inetAddressList: List<InetAddress>) {
        timings["dnsEnd"] = System.currentTimeMillis()
    }
    override fun connectStart(call: Call, inetSocketAddress: InetSocketAddress, proxy: Proxy) {
        timings["connectStart"] = System.currentTimeMillis()
    }
    override fun connectEnd(call: Call, inetSocketAddress: InetSocketAddress, proxy: Proxy, protocol: Protocol?) {
        timings["connectEnd"] = System.currentTimeMillis()
    }
    override fun secureConnectStart(call: Call) {
        timings["tlsStart"] = System.currentTimeMillis()
    }
    override fun secureConnectEnd(call: Call, handshake: Handshake?) {
        timings["tlsEnd"] = System.currentTimeMillis()
    }

    // ... 在 callEnd 时拼装完整 timing 数据
}
```

在 `OkHttpManager` 中注册：
```kotlin
builder.eventListenerFactory(MonitorEventListener.Factory(reporter))
```

### 11.2 采样率控制
高频接口可按配置的 `sampleRate` 采样上报，降低数据量：
```kotlin
private fun shouldSample(): Boolean {
    return Math.random() < config.sampleRate
}
```

### 11.3 本地持久化降级
当上报服务器不可达时，事件先写入本地 SQLite/文件，网络恢复后批量补报。

### 11.4 与现有日志系统整合
将 `IMonitorReportHandler` 的上报与 `HttpLogger` 的日志输出关联，形成"日志 + 监控"的双通道诊断体系。

### 11.5 监控面板
搭配服务端构建监控看板：
- 请求成功率趋势
- 各错误类型分布（DNS/连接/超时/HTTP错误）
- 慢请求 TOP N
- 分接口维度的 P50/P90/P99 耗时

## 十二、性能影响评估

| 环节 | 开销 | 说明 |
|------|------|------|
| 监控开关判断 | ~0.01ms | 两次 tag 读取 + 一次 boolean 判断 |
| 时间戳记录 | ~0.001ms | `System.currentTimeMillis()` 单次调用 |
| 事件对象构建 | ~0.05ms | 失败时才构建，正常路径返回 response |
| 异常分类 | ~0.02ms | 简单 when 分支判断 |
| 入队操作 | ~0.01ms | `LinkedBlockingQueue.offer()` 非阻塞 |
| JSON 序列化 | ~0.5ms | 在后台线程异步完成，不阻塞主路径 |
| HTTP 上报 | ~50-500ms | 独立 OkHttpClient + 后台线程，完全异步 |

**结论**：监控拦截器对主请求路径的额外开销 < 0.1ms，对用户体验无感知影响。
