# Net 库字段加密方案

## 背景

网络请求中需要对敏感字段（如手机号、身份证、密码等）进行传输加密。需要一个**对所有模块（net / net-flow / net-retrofit）统一生效**、**对业务代码透明**的加密方案。

---

## 方案选择：OkHttp Interceptor 拦截加密

### 为什么选 Interceptor

| 方案 | 覆盖范围 | 侵入性 | 结论 |
|---|---|---|---|
| OkHttp Interceptor | net / net-flow / net-retrofit 全部覆盖 | 零侵入，全局配置一次 | ✅ 推荐 |
| Retrofit Converter | 仅 net-retrofit | 需要替换 Converter | ❌ 覆盖面窄 |
| Builder 层 Hook | 仅 net 模块 | 需要修改每个 Builder | ❌ 覆盖面窄 + 侵入大 |
| 业务层手动加密 | 全量 | 每个请求需手动调用 | ❌ 易遗漏 |

OkHttp Interceptor 位于网络层最底层，所有请求（无论是 `Net.instance.get()`、`flowString()` 还是 Retrofit Service）都会经过它，一次配置全局生效。

---

## 架构设计

```
请求路径：

App 业务代码
  → Net.instance.get().send() / flowString() / Retrofit Service
    → OkHttpClient 拦截器链
      → EncryptInterceptor（加密请求字段）
        → LoggingInterceptor
          → 网络层 → 服务器

响应路径：

服务器 → 网络层
  → LoggingInterceptor
    → EncryptInterceptor（解密响应字段）
      → OkHttpClient 回调
        → DdCallback.onResponse / flowString().collect / Retrofit suspend
```

## 新增类设计

### 1. EncryptInterceptor —— 加解密拦截器

**文件**: `net/src/main/java/com/itg/net/encrypt/EncryptInterceptor.kt`

这是核心类，实现 `okhttp3.Interceptor`：

```
class EncryptInterceptor(
    private val config: EncryptConfig
) : Interceptor {

    // 请求拦截：
    // 1. 读取 request body 字符串
    // 2. 根据 EncryptRule 找到需要加密的字段
    // 3. 使用 Cipher 加密字段值
    // 4. 构造新的 RequestBody 返回

    // 响应拦截：
    // 1. 读取 response body 字符串
    // 2. 根据 EncryptRule 找到需要解密的字段
    // 3. 使用 Cipher 解密字段值
    // 4. 构造新的 ResponseBody 返回
}
```

### 2. EncryptConfig —— 加解密配置

**文件**: `net/src/main/java/com/itg/net/encrypt/EncryptConfig.kt`

```
class EncryptConfig {
    // 加密算法（AES / RSA / SM4）
    var algorithm: Algorithm = Algorithm.AES_CBC_PKCS7
    
    // 对称密钥（AES 使用）
    var secretKey: SecretKey? = null
    
    // 非对称公钥/私钥（RSA 使用）
    var publicKey: PublicKey? = null
    var privateKey: PrivateKey? = null
    
    // IV 向量（AES CBC 模式）
    var iv: ByteArray? = null
    
    // 字段加密规则列表
    val rules: MutableList<EncryptRule> = mutableListOf()
    
    // 是否启用请求加密
    var requestEncryptEnabled: Boolean = true
    
    // 是否启用响应解密
    var responseDecryptEnabled: Boolean = true
    
    // 是否跳过 GET 请求（GET 通常无 body）
    var skipGetRequest: Boolean = true
}
```

### 3. EncryptRule —— 加密规则

**文件**: `net/src/main/java/com/itg/net/encrypt/EncryptRule.kt`

```
sealed class EncryptRule {

    // 按字段名匹配（精确匹配 JSON key）
    data class ByFieldName(
        val fieldName: String,          // 如 "phone"、"password"、"idCard"
        val direction: Direction = Direction.BOTH  // 加密方向
    ) : EncryptRule()

    // 按字段名正则匹配
    data class ByFieldPattern(
        val pattern: Regex,             // 如 Regex(".*[Pp]assword.*")
        val direction: Direction = Direction.BOTH
    ) : EncryptRule()

    // 按请求路径匹配
    data class ByPath(
        val pathPattern: Regex,         // 如 Regex("/user/.*")
        val fieldNames: List<String>,   // 该路径下需要加密的字段
        val direction: Direction = Direction.BOTH
    ) : EncryptRule()
}

enum class Direction {
    REQUEST_ONLY,    // 仅请求加密
    RESPONSE_ONLY,   // 仅响应解密
    BOTH             // 双向加解密
}
```

### 4. Algorithm —— 加密算法枚举

**文件**: `net/src/main/java/com/itg/net/encrypt/Algorithm.kt`

```
enum class Algorithm {
    AES_CBC_PKCS7,       // AES/CBC/PKCS7Padding（最常用）
    AES_ECB_PKCS7,       // AES/ECB/PKCS7Padding
    AES_GCM_NO_PADDING,  // AES/GCM/NoPadding（推荐，带认证）
    RSA_ECB_PKCS1,       // RSA/ECB/PKCS1Padding（非对称）
    SM4_CBC_PKCS7        // 国密 SM4（金融场景）
}
```

### 5. EncryptUtil —— 加解密工具类

**文件**: `net/src/main/java/com/itg/net/encrypt/EncryptUtil.kt`

```
object EncryptUtil {
    fun encrypt(plaintext: String, config: EncryptConfig): String
```

## 配置方式：集成到 NetConfig DSL

在 `NetConfig` 中新增 `encrypt` 配置块，保持与现有 DSL 风格一致：

```kotlin
// 在 Application.onCreate() 中一次性配置
Net.instance.configure {
    app(this@MyApp)
    url("https://api.example.com")
    
    // 字段加密配置
    encrypt {
        // 算法：AES CBC
        algorithm(Algorithm.AES_CBC_PKCS7)
        
        // 密钥（从服务端协商或本地预置）
        secretKey("my-32-byte-secret-key!!".toByteArray())
        
        // IV 向量
        iv("1234567890abcdef".toByteArray())
        
        // 规则1：按字段名精确匹配
        encryptField("phone")              // 请求+响应双向加密
        encryptField("password")           // 同上
        encryptField("idCard")
        
        // 规则2：响应才解密
        decryptField("realName")           // 仅响应解密
        
        // 规则3：正则匹配
        encryptPattern(Regex(".*[Ss]ecret.*"))
        
        // 规则4：按请求路径 + 字段组合匹配
        encryptPath(Regex("/user/.*"), listOf("phone", "email"))
        
        // 开关
        requestEncrypt(true)               // 启用请求加密（默认）
        responseDecrypt(true)              // 启用响应解密（默认）
        skipGetRequest(true)               // 跳过 GET 请求（默认）
    }
}
```

> 进入 `encrypt { }` 闭包后，`this` 为 `EncryptConfig` 实例。

## 实现原理

### 请求加密流程

```
原始请求 Body：
{"username":"admin","password":"123456","phone":"13800138000"}

EncryptInterceptor 处理：
1. 读取 body → 字符串
2. 检测是 JSON 格式（以 { 或 [ 开头）
3. 遍历 EncryptRule：
   - ByFieldName("password") 命中 → AES 加密 "123456" → "a8f5e2d9..."
   - ByFieldName("phone") 命中 → AES 加密 "13800138000" → "b3c7f1a8..."
4. 替换 JSON 中对应字段的值
5. 构造新 RequestBody（Content-Type 不变）

发送到服务器的 Body：
{"username":"admin","password":"a8f5e2d9...","phone":"b3c7f1a8..."}
```

### 响应解密流程

```
服务器返回 Body：
{"code":200,"data":{"phone":"b3c7f1a8...","realName":"d1e6c4f8..."}}

EncryptInterceptor 处理：
1. 读取 body → 字符串
2. 遍历 EncryptRule，对密文字段执行 AES 解密
3. 替换 JSON 中对应字段的值

返回给业务层的 Body：
{"code":200,"data":{"phone":"13800138000","realName":"张三"}}
```

### JSON 路径处理

对于嵌套 JSON，使用 "." 分隔路径：

```json
{
  "user": {
    "phone": "encrypted_value",    ← "user.phone" 命中
    "address": {
      "detail": "encrypted_value"  ← "user.address.detail" 命中
    }
  }
}
```

### 非 JSON Body 处理

对于 Form 表单（`application/x-www-form-urlencoded`），按 `key=value&key=value` 格式解析，对匹配的 key 对应的 value 进行加解密。

对于纯文本 / 二进制 body，不处理（无法识别字段边界）。

## 使用场景示例

### 场景 1：登录接口密码加密

```kotlin
// 配置（一次性）
Net.instance.configure {
    encrypt {
        algorithm(Algorithm.AES_CBC_PKCS7)
        secretKey(secretKeyBytes)
        iv(ivBytes)
        encryptField("password")     // 密码加密
        encryptField("smsCode")      // 短信验证码加密
    }
}

// 业务代码完全无感
Net.instance.postJson()
    .url("https://api.example.com/login")
    .addParam("username", "admin")
    .addParam("password", "123456")    // ← 自动加密
    .send(callback)
// 发送：{"username":"admin","password":"a8f5e2d9..."}
```

### 场景 2：用户信息接口双向加密

```kotlin
Net.instance.configure {
    encrypt {
        // 请求时加密手机号，响应时解密手机号和真实姓名
        encryptField("phone")        // 双向
        decryptField("realName")     // 仅解密
    }
}

// 修改手机号（请求加密）
Net.instance.postJson()
    .url("https://api.example.com/user/update")
    .addParam("phone", "13800138000")   // ← 自动加密
    .send(callback)

// 获取用户信息（响应解密）
Net.instance.get()
    .url("https://api.example.com/user/1")
    .send(object : DdCallback {
        override fun onResponse(result: String?, code: Int) {
            // result 中的 phone 和 realName 已自动解密
        }
    })
```

### 场景 3：Retrofit 场景同样生效

```kotlin
interface UserService {
    @POST("user/login")
    suspend fun login(@Body request: LoginRequest): LoginResponse
}

// 无需任何额外处理，EncryptInterceptor 在 OkHttp 层自动加解密
val result = userService.login(LoginRequest(phone = "13800138000", password = "123456"))
// 发送的 body 中 phone 和 password 已加密
// 返回的 response 中敏感字段已解密
```

### 场景 4：按接口路径差异化加密

```kotlin
Net.instance.configure {
    encrypt {
        secretKey(keyBytes)
        iv(ivBytes)
        
        // /user/* 接口加密手机号和邮箱
        encryptPath(Regex("/user/.*"), listOf("phone", "email"))
        
        // /payment/* 接口额外加密银行卡号
        encryptPath(Regex("/payment/.*"), listOf("phone", "bankCard", "cvv"))
        
        // 全局规则：所有接口加密密码
        encryptField("password")
    }
}
```

## 密钥管理建议

| 方式 | 安全等级 | 适用场景 |
|---|---|---|
| 本地预置固定密钥 | ⭐ | 开发/测试环境 |
| 服务端协商（登录后下发 SessionKey） | ⭐⭐⭐ | 生产环境推荐 |
| 证书绑定 + RSA 传输 AES 密钥 | ⭐⭐⭐⭐ | 高安全需求 |
| Android Keystore 硬件保护 | ⭐⭐⭐⭐⭐ | 金融/支付场景 |

推荐做法：
1. App 启动时生成 RSA 密钥对，公钥发给服务端
2. 服务端用公钥加密 AES SessionKey 返回
3. 后续请求全部使用该 AES SessionKey 进行字段加解密
4. SessionKey 定期轮换

## 性能影响

- **加密开销**：AES-GCM 加密 1KB 数据约 0.1ms，对用户体验基本无影响
- **拦截器顺序**：EncryptInterceptor 应放在 LoggingInterceptor 之前，这样日志中看到的是加密后的密文，不泄露敏感信息
- **跳过非 JSON Body**：对文件上传（二进制 body）自动跳过，不影响大文件传输性能
