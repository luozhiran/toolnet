# 加密模式方案 —— 少量接口加密 / 大量接口加密 双模式

## 背景

前两个方案分别解决了"全部加密"和"指定跳过"，但它们隐含了一个假设：**大部分接口需要加密**。

实际业务中还有另一种场景：**只有少数接口需要加密**（如仅登录和支付接口），其余接口全部透传。如果沿用"全量加密 + 逐个跳过"的模式，需要为大量不需要加密的接口手动添加跳过规则，繁琐且易遗漏。

需要一个模式切换，让库同时支持两种场景。

---

## 方案：EncryptMode 双模式

在 `EncryptConfig` 中新增 `EncryptMode` 枚举：

```kotlin
enum class EncryptMode {
    /** 大部分接口需要加密 —— 全局规则生效，通过 skipPath 排除 */
    OPT_OUT,

    /** 只有少数接口需要加密 —— 仅 encryptPath 匹配的接口才加密 */
    OPT_IN
}
```

### 模式一：OPT_OUT（默认）—— 大部分接口加密，少数跳过

```kotlin
encrypt {
    encryptMode(EncryptMode.OPT_OUT)   // 默认值，可省略
    algorithm(Algorithm.AES_GCM_NO_PADDING)
    secretKey(sessionKey)
    iv(sessionIv)

    // 全局规则：所有接口的这两个字段都加密
    encryptField("password")
    encryptField("phone")

    // 排除不需要加密的接口
    skipPath(Regex("/public/.*"))
    skipPath(Regex("/health-check"))
}
```

### 模式二：OPT_IN —— 仅指定接口加密，其余全部透传

```kotlin
encrypt {
    encryptMode(EncryptMode.OPT_IN)    // 开启按需加密模式
    algorithm(Algorithm.AES_GCM_NO_PADDING)
    secretKey(sessionKey)
    iv(sessionIv)

    // 只有这些接口会加密，其他接口直接透传
    encryptPath(Regex("/user/login"), listOf("password"))
    encryptPath(Regex("/user/.*"), listOf("phone", "email", "idCard"))
    encryptPath(Regex("/payment/.*"), listOf("bankCard", "cvv", "amount"))
}
```

---

## 两种模式行为对比

| | OPT_OUT（默认） | OPT_IN |
|---|---|---|
| `encryptField("pwd")` | ✅ 所有接口都加密 pwd | ⚠️ 忽略（无意义） |
| `encryptPath("/user/.*", ["phone"])` | ✅ /user/* 接口加密 phone | ✅ 仅 /user/* 接口加密 phone |
| `skipPath("/public/.*")` | ✅ 跳过 /public/* | ⚠️ 忽略（本来就不会加密） |
| 未匹配任何规则的接口 | ✅ 全局规则仍生效 | ❌ 直接透传，零开销 |
| 典型场景 | 全站加密（安全要求高） | 仅敏感接口加密（性能要求高） |

## 需要新增/改动的代码

### 新增：EncryptMode 枚举

**文件**: `EncryptConfig.kt` 同级目录，新增 `EncryptMode.kt`：

```kotlin
enum class EncryptMode {
    OPT_OUT,  // 全量加密 + skipPath 排除
    OPT_IN    // 按需加密，仅 encryptPath 匹配的生效
}
```

### 改动：EncryptConfig

**文件**: `EncryptConfig.kt`，新增属性和 DSL 方法：

```kotlin
// 属性（默认 OPT_OUT，向后兼容）
var encryptMode: EncryptMode = EncryptMode.OPT_OUT

// DSL 方法
fun encryptMode(mode: EncryptMode): EncryptConfig {
    this.encryptMode = mode
    return this
}
```

### 改动：EncryptInterceptor —— 入口逻辑

**文件**: `EncryptInterceptor.kt`，修改 `intercept()` 方法：

```kotlin
override fun intercept(chain: Interceptor.Chain): Response {
    var request = chain.request()

    if (config.requestEncryptEnabled && config.hasValidConfig()) {
        if (shouldEncryptRequest(request)) {       // ← 新增判断
            request = encryptRequest(request)
        }
    }

    val response = chain.proceed(request)

    if (config.responseDecryptEnabled && config.hasValidConfig()) {
        if (shouldDecryptResponse(response)) {      // ← 新增判断
            return decryptResponse(response)
        }
    }

    return response
}

private fun shouldEncryptRequest(request: Request): Boolean {
    // OPT_IN 模式：仅当请求路径匹配任一 encryptPath 规则时才加密
    if (config.encryptMode == EncryptMode.OPT_IN) {
        return matchesAnyEncryptPath(request.url.encodedPath, forEncrypt = true)
    }
    // OPT_OUT 模式：未命中 skipPath 就加密
    return !matchesAnySkipPath(request.url.encodedPath)
}
```

### 改动：EncryptInterceptor —— 筛选逻辑优化

`matchesAnyEncryptPath()` 检查当前请求路径是否命中至少一个 `EncryptRule.ByPath` 规则。如果没有任何 `ByPath` 规则，OPT_IN 模式下加密完全不会生效——这是预期行为，因为 OPT_IN 依赖 `encryptPath()` 工作。

```kotlin
/**
 * OPT_IN 模式下判断请求路径是否命中至少一个加密规则
 */
private fun matchesAnyEncryptPath(requestPath: String, forEncrypt: Boolean): Boolean {
    for (rule in config.rules) {
        if (forEncrypt && rule.direction == Direction.RESPONSE_ONLY) continue
        if (!forEncrypt && rule.direction == Direction.REQUEST_ONLY) continue

        when (rule) {
            is EncryptRule.ByPath -> {
                if (rule.pathPattern.matches(requestPath)) return true
            }
            is EncryptRule.ByFieldName -> {
                // OPT_IN 模式下 ByFieldName 也被视为全局匹配
                // 保持语义清晰：OPT_IN 下建议只使用 encryptPath
            }
            is EncryptRule.ByFieldPattern -> {
                // 同上
            }
        }
    }
    return false
}
```

## 完整示例

### 场景 A：金融 App（少数接口加密）

```kotlin
// Application 初始化
Net.instance.configure {
    encrypt {
        encryptMode(EncryptMode.OPT_IN)       // ← 按需加密模式
        algorithm(Algorithm.AES_GCM_NO_PADDING)
        secretKey(sessionKey)
        iv(sessionIv)

        // 只有这些路径会触发加密
        encryptPath(Regex("/user/login"), listOf("password"))
        encryptPath(Regex("/user/register"), listOf("password", "idCard"))
        encryptPath(Regex("/payment/.*"), listOf("bankCard", "cvv", "amount"))
        encryptPath(Regex("/wallet/transfer"), listOf("amount", "payPassword"))
    }
}

// 登录接口 —— 自动加密
Net.instance.postJson()
    .url("https://api.example.com/user/login")
    .addParam("password", "123456")
    .send(callback)
// → password 加密，因为 /user/login 匹配 encryptPath

// 新闻列表 —— 直接透传
Net.instance.get()
    .url("https://api.example.com/news/list")
    .send(callback)
// → 零开销透传，不经过 JSON 解析
```

### 场景 B：企业应用（大量接口加密）

```kotlin
Net.instance.configure {
    encrypt {
        encryptMode(EncryptMode.OPT_OUT)      // ← 全量加密模式（默认）
        algorithm(Algorithm.AES_GCM_NO_PADDING)
        secretKey(sessionKey)
        iv(sessionIv)

        encryptField("password")
        encryptField("phone")

        // 仅公开接口跳过
        skipPath(Regex("/public/.*"))
        skipPath(Regex("/health-check"))
    }
}
```

### 场景 C：开发/测试环境不加密，生产环境加密

```kotlin
Net.instance.configure {
    encrypt {
        encryptMode(
            if (BuildConfig.DEBUG) EncryptMode.OPT_IN  // 开发环境不加密
            else EncryptMode.OPT_OUT                    // 生产环境全量加密
        )
        algorithm(Algorithm.AES_GCM_NO_PADDING)
        secretKey(sessionKey)
        iv(sessionIv)

        if (BuildConfig.DEBUG) {
            // 开发环境仅加密这一个接口做测试
            encryptPath(Regex("/test/encrypt"), listOf("data"))
        } else {
            // 生产环境全量加密
            encryptField("password")
            encryptField("phone")
            encryptField("idCard")
            skipPath(Regex("/public/.*"))
        }
    }
}
```

## 性能对比

以一个有 50 个接口的 App 为例，其中 3 个接口需要加密（登录、支付、个人信息）：

| | OPT_OUT + skipPath | OPT_IN（本方案） |
|---|---|---|
| 需手动跳过的接口数 | 47 个 | 0 个 |
| 无匹配时 JSON 解析开销 | 47 次 × 0.5ms = 23.5ms/冷启动 | 0ms |
| 配置维护成本 | 高（新增接口可能漏加 skipPath） | 低（新增接口默认不加密） |
| 安全性 | 高（默认加密，不易遗漏） | 中（新增接口需主动加 encryptPath） |
