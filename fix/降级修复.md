# 降级修复 —— Linter 自动升级依赖导致编译失败

## 故障现象

执行 `./gradlew clean build` 报错：

```
e: Incompatible classes were found in dependencies.
e: Module was compiled with an incompatible version of Kotlin.
   The binary version of its metadata is 2.1.0/2.2.0, expected version is 1.8.0.

e: Unresolved reference: awaitClose / callbackFlow / trySend / close

e: Dependency requires compileSdkVersion 33+, current is 31.
```

## 根本原因

Linter（Android Studio / IDE 的依赖检查工具）在 `net-flow/build.gradle`、`net-retrofit/build.gradle`、`app/build.gradle` 中自动将依赖升级到了最新版本。这些新版本是用 **Kotlin 2.0+ 编译器**编译的，其 Kotlin metadata 二进制版本为 2.1.0 / 2.2.0，而项目使用的 Kotlin 编译器版本为 **1.8.20**，只能读取 metadata 版本 ≤ 1.9.0 的 class 文件，导致 `Incompatible classes` 错误。

### Kotlin metadata 版本兼容关系

| Kotlin 编译器版本 | 可读取的 metadata 版本 |
|---|---|
| 1.6.x | ≤ 1.6.0 |
| 1.7.x | ≤ 1.7.0 |
| 1.8.x | ≤ 1.9.0 |
| 1.9.x | ≤ 2.0.0 |
| 2.0.x | ≤ 2.1.0 |

## 修复内容

### 1. net-flow/build.gradle

| 依赖 | 错误版本 | 修复版本 | 原因 |
|---|---|---|---|
| `kotlinx-coroutines-core` | 1.11.0 | 1.7.3 | 1.11.0 用 Kotlin 2.2.0 编译，1.7.3 兼容 1.8.x |
| `kotlinx-coroutines-android` | 1.11.0 | 1.7.3 | 同上 |
| `androidx.appcompat:appcompat` | 1.7.1 | **移除** | 不需要直接依赖，由 `net` 模块 `api` 传递 |
| `androidx.core:core-ktx` | 1.19.0 | **移除** | 同上，由 `net` 模块传递 |
| `com.google.android.material` | 1.14.0 | **移除** | 库模块不需要 Material 依赖 |
| `com.google.code.gson:gson` | 2.14.0 | 2.9.0 | 无 metadata 影响，仅保持版本一致性 |
| `androidx.test.espresso` | 3.7.0 | 3.4.0 | 与 net 模块测试依赖版本对齐 |
| `androidx.test.ext:junit` | 1.3.0 | 1.1.3 | 与 net 模块测试依赖版本对齐 |

### 2. net-retrofit/build.gradle

| 依赖 | 错误版本 | 修复版本 | 原因 |
|---|---|---|---|
| `retrofit` | 3.0.0 | 2.9.0 | 3.0.0 需要更高 Kotlin 版本；2.9.0 兼容 OkHttp 4.9.2 + Kotlin 1.8.x |
| `converter-gson` | 3.0.0 | 2.9.0 | 同上 |
| `androidx.appcompat:appcompat` | 1.7.1 | **移除** | 与 net-flow 同理 |
| `androidx.core:core-ktx` | 1.19.0 | **移除** | 同上 |
| `com.google.android.material` | 1.14.0 | **移除** | 同上 |
| `androidx.test.espresso` | 3.7.0 | 3.4.0 | 版本对齐 |
| `androidx.test.ext:junit` | 1.3.0 | 1.1.3 | 版本对齐 |

### 3. app/build.gradle

| 依赖 | 错误版本 | 修复版本 | 原因 |
|---|---|---|---|
| `kotlinx-coroutines-android` | 1.11.0 | 1.7.3 | 与 net-flow 同理 |
| `converter-scalars` | 3.0.0 | **移除** | 不需要，且同样有版本兼容问题 |
| `lifecycle-runtime-ktx` | **缺失** | 新增 2.3.1 | `lifecycleScope` 扩展需要此依赖 |
| `project(':net')` | 被移除 | **恢复** | Linter 误删 |
| `project(':net-flow')` | 被移除 | **恢复** | Linter 误删 |

### 4. app/App.kt

| 问题 | 修复 |
|---|---|
| `import retrofit2.converter.scalars.ScalarsConverterFactory` | 移除（依赖已删除） |
| `ScalarsConverterFactory.create()` 调用 | 移除 |

## 预防措施

1. **锁定关键依赖版本**：在 `build.gradle` 中使用精确版本号（`1.7.3` 而非 `1.+`），防止 Linter 或 IDE 自动升级
2. **统一版本管理**：考虑使用 `gradle.properties` 或 `buildSrc` 集中管理依赖版本号
3. **Kotlin 与协程版本绑定**：`kotlinx-coroutines` 的大版本必须与 Kotlin 编译器版本匹配，升级 Kotlin 时需同步升级协程库
